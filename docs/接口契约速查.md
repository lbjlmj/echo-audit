# Echo 后端接口契约速查（v1 ｜ 2026-10-28 ｜ 对应后端 113 tests 全绿基线）

> 面向前端铺底的路由级速查。出入参详细结构以运行时 OpenAPI 为准：启动后端后打开 `http://localhost:8000/docs`（Swagger UI）或 `/openapi.json`。
> 本文档按域汇总 11 个路由域共 86 个端点，标注权限码、行为要点与错误码段。

## 1. 全局约定

| 项 | 约定 |
| --- | --- |
| Base URL | `/api/v1`（健康检查 `GET /health` 不带前缀） |
| 鉴权 | `Authorization: Bearer <JWT>`；登录 `POST /auth/login` 签发，`GET /auth/me` 返回当前用户与权限矩阵视图（前端按此渲染菜单/按钮，路由守卫仅兜底，权限以后端为准） |
| 错误码格式 | `<域段>-<4 位>`，置于 HTTP `detail` 首段（如 `PR-1001 ...`）。状态语义：401 未认证 / 403 无权限 / 404 不存在 / 409 冲突（状态机拒绝·重复操作·封印不一致）/ 422 业务校验拒绝 / 500 内部 |
| 幂等与留痕 | 状态变更类接口幂等；所有写操作落审计留痕（哈希链 append-only）；AI 产物一律「线索态」，须经人工确认接口采信后才生效（前端须先展示线索、再提交确认） |
| 权限等级 | 级别从低到高：`NONE < VIEW < OPERATE < PROPOSE < APPROVE`；下表「权限」列格式为 `权限码 ≥ 等级` |

## 14. AI 生成式通道约定（前端须知）

- **Phase 1 大模型通道默认关闭**（§15-15）：所有「AI」端点（risk-ai / ai-draft / anomaly-scan / classify / notes-draft / qc-checks / qa）均为纯规则实现，`model_version` 形如 `rule-*-v1`；前端无须区分通道，按线索态 → 人工确认交互即可。
- 线索态产物的确认模式统一为：`POST .../review` 或 `POST .../confirm`（采信/不采信 + 枚举原因）。
- AI 使用过程 100% 留痕可反查：`GET` 留痕经审计日志域回放（历史问答 `GET /knowledge/qa` 同口径）。
